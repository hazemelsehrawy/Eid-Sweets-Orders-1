## 1. الأهداف ونطاق العمل (Goal & Scope)

### 1.1 الهدف الأساسي (Core Objective)
تمكين طاقم العمل ومسؤولي الكاشير في محل حلويات فتوح (Eid Sweets) من إنشاء وحفظ وتسليم طلبيات البيع الفوري للعملاء المتواجدين أمام الكاونتر داخل المحل حالياً ("زبون الصالة / العميل المباشر") بأقصى سرعة ممكنة وبأقل عدد من النقرات، مع تسجيل الطلب مباشرة بحالة **مستلم (`delivered`)** وحالة سداد **مدفوع بالكامل (`paid`)**، وخصم المخزون الفعلي للأصناف تلقائياً وبشكل نهائي، وطباعة إيصال الاستلام الحراري (72mm) فوراً.

### 1.2 الفئة المستهدفة وحالة الاستخدام (Target Audience & Use Case)
- **الكاشير وموظفو المبيعات بالمحل (Store Cashier & Counter Staff)**: أثناء فترات الذروة وازدحام طوابير العيد، يحتاج الكاشير لتسجيل طلبات العملاء الذين يستلمون حلوياتهم ويدفعون فوراً دون الحاجة لإدخال بيانات مطولة أو المرور بمراحل التعليق والتجهيز المخصصة للطلبات المسبقة عبر الإنترنت.

## 2. المتطلبات الوظيفية (Functional Requirements)

### 2.1 حقول وبيانات الطلب الفوري (Data Minimization for Speed)
1. **رقم الموبايل (Customer Phone)**: الحقل الوحيد المطلوب إدخاله من الكاشير (للتعريف وإمكانية متابعة البون أو إرساله عبر واتساب)، مع خيار زر سريع لتعبئة رقم افتراضي للعملاء الذين لا يرغبون بترك رقمهم.
2. **اسم العميل (Customer Name)**: يتم تعيينه تلقائياً ودون إدخال يدوي إلى: `"عميل مباشر"` (أو `"زبون المحل"`).
3. **رقم الطلب (Order Number)**: يتم توليده تلقائياً وفريداً عبر النظام مثل: `EID-XXXX-XXXX`.
4. **تاريخ ووقت الاستلام (Pickup Date & Time)**: يتم تعيينهما تلقائياً إلى تاريخ اليوم الحالي (`Africa/Cairo`) والوقت الحالي لحظة البيع.
5. **طريقة الدفع (Payment Method)**: اختيار سريع بنقرة واحدة بين:
   - نقداً (Cash - الافتراضي)
   - إنستاباي (InstaPay)
   - بطاقة بنكية / فيزا (Card)
   - فودافون كاش (Vodafone Cash)
6. **الحالة وحسابات السداد (Status & Financials)**:
   - حالة الطلب (`status`): `delivered` (مستلم).
   - حالة الدفع (`paymentStatus`): `paid` (مدفوع بالكامل).
   - العربون (`depositAmount`): يساوي إجمالي الطلب كاملاً (`totalPrice`).
   - المتبقي (`remainingBalance`): `0.00`.
   - منشئ الطلب (`createdBy`): `admin`.

### 2.2 شاشة وواجهة الكاشير السريع (Quick POS Modal Interface)
1. **زر الوصول السريع**: زر بارز ودائم في أعلى شريط لوحة التحكم (`Admin Header`) وشاشة الطلبات:
   `⚡ + طلب فوري (كاشير)` / `+ Quick POS Order`.
2. **شبكة أصناف الحلويات (Sweets Quick Grid)**:
   - عرض فئات وأصناف الكعك والحلويات المتاحة في بطاقات واضحة الملامح.
   - لكل صنف: إظهار السعر والمخزون المتاح، مع أزرار سريعة بنقرة واحدة:
     - `+ 1 كجم`
     - `+ ½ كجم` (للأصناف التي تباع بالكيلو ونصف الكيلو)
     - `+ 1 علبة` (للأصناف التي تباع بالعلبة)
   - حقل بحث سريع لتصفية الأصناف فوراً أثناء كتابة الاسم.
3. **تذكرة الفاتورة اللحظية (Live Ticket Sidebar / Drawer)**:
   - استعراض الأصناف المضافة والكميات وأزرار التعديل (+ / - / حذف).
   - إجمالي الحساب التراكمي المحدث لحظياً.
   - حقل رقم الموبايل.
   - أزرار وسيلة الدفع.
4. **الإجراء النهائي والطباعة (Instant Fulfill & Print)**:
   - زر كبير ملون `🖨️ إتمام البيع وطباعة الإيصال`.
   - بمجرد الضغط:
     1. إرسال الطلب للسيرفر وحفظه.
     2. فتح نافذة طباعة إيصال البون الحراري 72mm تلقائياً.
     3. تشغيل صوت تنبيه النجاح الخفيف.
     4. إعادة تهيئة التذكرة لخدمة الزبون التالي في الطابور مباشرة.

## 3. المعمارية والبيانات (Architecture & Backend Integration)

### 3.1 المعالجة الذرية للسيرفر وقاعدة البيانات (Atomic Database Transaction)
في مسار `POST /api/orders`:
- إضافة دعم صريح للحقلين الاختياريين `status?: 'pending' | 'delivered'` و `paymentStatus?: 'paid' | 'unpaid'`.
- إذا تم إرسال الطلب بحالة `status === 'delivered'`:
  1. إنشاء الطلب مباشرة بحالة `delivered` وحالة سداد `paid`.
  2. داخل نفس المعاملة الذرية (`db.transaction`)، يتم خصم الكميات المطلوبة فوراً من المخزون الفعلي (`stockQuantity` للأصناف بالكيلو أو العلبة، و `halfKiloStock` لعبوات نصف الكيلو في جدول `categories`).
  3. منع حدوث أي نقص أو بيع لكميات غير متوفرة عبر فحص المخزون قبل الحفظ (`InsufficientStockError`).
  4. هذا يضمن سلامة دورة حياة المخزون بالكامل دون الحاجة لإرسال استدعاءين منفصلين للشبكة.

### 3.2 تحديث واجهة العميل (`App.tsx` & `@/components/receipt/PrintableReceipt`)
1. مكون `QuickOrderPosModal` التفاعلي السريع.
2. زر التشغيل في شريط رأس الإدارة `AdminShell` وشاشة الطلبات `OrdersPage`.
3. تكامل مباشر مع `PrintableReceipt` لبدء أمر الطباعة فور حفظ الطلب.
